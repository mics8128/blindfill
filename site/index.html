Your AI agent signs in. It never sees the password.

blindfill connects your password manager, such as Bitwarden, to the browser and types the credential straight into the login field. The agent picks the account; the password never enters the model's context.

Get started View on GitHub

Open source under MIT, on npm. Alpha: not yet independently reviewed.

The password goes from vault to form, not through the model

The agent names an account and a page. blindfill does the rest and reports only the outcome.

  1. The agent names an item and a URL

    It can't choose where the secret goes. The target comes from the item's own URIs.

  2. blindfill verifies the site

    The origin the browser reports must match the item. Lookalike domains and cross-origin iframes are refused before any secret is read.

  3. The form is filled, then the session locks

    The form is submitted at most once. Afterwards page text, DOM and screenshots are refused, and all output is scrubbed.

Secrets stay out of the model's context

blindfill runs on your machine and reads from your password manager's own CLI. Call it as a CLI, an MCP server over stdio, or a TypeScript library on your own Playwright page.

Fill-only secrets

Passwords, hidden fields and card numbers can only be typed into a field. TOTP seeds and private keys are never typed anywhere. No CLI command, MCP tool or library call returns any of them.

Bound to the right site

The vault item and the observed origin decide where a secret is typed, not the agent. A page can't redirect it.

Locked after fill

Once a secret is filled, page text, DOM and screenshots are refused, and every output is scrubbed.

Stops instead of guessing

Ambiguous fields, origin mismatches and unknown outcomes are reported, never retried. Honeypot fields are skipped.

What the agent can read

Class Examples Read Fill
Secret Password, hidden custom fields, card number and CVV Never Yes
Key TOTP seed, SSH private keys, passkey private keys Never Never (a passkey only signs)
Ephemeral The current TOTP code Yes Yes
Readable Username, item name, URIs, text fields Yes Yes
Notes Free-form notes, which may hold secrets Off by default; opt in per item No

The class comes from the field type in your vault. Unknown data is treated as Secret. A canary leak test searches every output and state file for the password. Read SECURITY.md

Compared with common approaches

How each approach typically handles the password. Products vary, so check the one you use.

Comparison of approaches to giving an agent a login
Approach Password enters the model's context Who decides where it's typed Where it runs
blindfill Not by design: secret values are fill-only The vault item, checked against the browser's origin Your machine, with your vault CLI
Password in the prompt Yes The model Wherever the model runs
Password manager CLI given to the agent Usually: the CLI prints plaintext to its caller The model Your machine
Browser extension autofill Usually not at fill time; depends on what the agent reads later The extension's site matching Your browser
Cloud browser service Depends on the vendor Varies The vendor's infrastructure

The post-fill lock covers blindfill's own interfaces only. Another tool attached to the same browser can still read the page.

Know the limits before you rely on it

Not built yet

  • Android in real apps: sign-up, WebView and Credential Manager passwords, passkey registration (tested with a fake app only). Saving logins typed by hand.
  • WebKit / Safari.
  • Shadow DOM, closed iframes and canvas inputs. blindfill stops when it meets them.
  • Sites that block automation or need a person (bot checks, some MFA setups); see TESTED.md. The other six backends have never run on a real vault.
  • An independent security review.

Outside the threat model

blindfill protects against the model and its logs. It does not protect against:

  • A malicious or compromised page. Scripts on a page you bound the item to can read the typed password.
  • A compromised browser or machine that can read process memory, the profile or your vault session.
  • Another tool attached to the same browser, which can read a filled field.
  • A page that transforms the secret. Scrubbing is best effort.

Read the full threat model in SECURITY.md

Questions

Does the model ever see my password?

Not through blindfill: no command, tool or function returns a Secret-class value. Once typed, the password is in the page's DOM, where another browser tool could read it. If that matters, give the agent blindfill instead of an unrestricted browser tool for the same session.

Can it read my one-time codes?

Yes, the current code is readable and fillable like text. The TOTP seed is never returned. The code's safety rests on origin binding and its short lifetime.

How does my agent call it?

Through the blindfill CLI, the MCP server over stdio (blindfill mcp), or the TypeScript library with your own Playwright page.

Is it safe for my real accounts?

It's alpha software with no independent review. Start with throwaway or low-stakes accounts and read the threat model first.

Install

You need Node 20 or newer and, for the Bitwarden backend, the Bitwarden CLI (bw). Use your own Chromium with --executable, or install Playwright's build once. 

npm i -g blindfill
npx playwright-core install chromium
export BW_SESSION="$(bw unlock --raw)"   # env only
mkdir -p ~/.config/blindfill && echo '{"backend":"bw"}' > ~/.config/blindfill/config.json
blindfill session start --headless
blindfill fill --item <id> --url https://example.com/login --submit
