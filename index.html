Today's options for agent logins are all a bit awkward

To get an agent past a login page you usually paste the password into the prompt, or hand it a password-manager CLI whose commands return plaintext. Either way the secret enters the model's context, and from there it can reach transcripts, logs and tool output. blindfill is a different shape: the agent picks which account and which page, and never receives the value.

How it works

The password takes a short trip that skips the model entirely. Only the outcome comes back.

  1. The agent asks

    It names a vault item and a login URL. It never chooses where the secret goes: binding comes from the item's own URIs.

  2. blindfill checks the page

    The origin the browser actually reports is compared with the item's binding. A lookalike domain or a cross-origin iframe is refused before any secret is read.

  3. The secret is typed, then sealed

    The value goes from the vault into the field and the form is submitted at most once. Afterwards the session refuses page text, DOM and screenshots, and output is scrubbed.

The hard parts, handled by design

Fill-only secrets

Passwords, TOTP seeds, hidden fields, card numbers and private keys can be written into a field, never returned. No CLI command, MCP tool or library function hands one back.

Readable where it helps

Usernames, item names, URIs, text fields and the current one-time code are readable so the agent can reason and act. The TOTP seed itself stays in the backend.

Phishing and injection resistant

A page can't talk the agent into typing the password elsewhere: the target is decided by the vault item and the observed origin, not by the caller.

Fails closed

Honeypot fields are skipped. An ambiguous field, an origin mismatch or an unknown outcome makes blindfill stop and report. It doesn't guess and doesn't retry.

CLI, MCP and library

Use the blindfill CLI, an MCP server over stdio, or the TypeScript library with your own Playwright page.

Tested with a canary

A leak test fills a canary password and searches all output and state files for it. It's one safety net, not a proof.

What's supported today

Status as of main (commit fa64962, 0.1.0-alpha.0), from the repo's docs: README, browsers.md.

Password managers

  • mock-verified Bitwarden / Vaultwarden (bw): tested against a mock CLI and fixtures. Not yet tested end to end on a live vault.
  • blind-written 1Password (op), rbw, pass, gopass, KeePassXC, Secret Service: pass contract tests on recorded fixtures only. Never touched a real vault.

Browsers and platforms

  • supported, tested Chromium: Playwright's bundled build, any Chromium build via --executable, or loopback CDP.
  • opt-in Firefox / Camoufox: via a loopback Playwright server, tested in an opt-in suite against Camoufox 158.0.1-beta.41 and 159.0-beta.43. A long-running instance of your own is untested.
  • separate instance Ego Lite: works only as a separately launched instance with an empty profile. It can't attach to the one you're already running.
  • limited Passkeys: web sign-in on Chromium (CDP virtual authenticator) and Android app sign-in (signed on the host), tested against fake relying parties. No counter write-back, no registration.
  • not supported WebKit/Safari: not supported. Android: companion APK (Android 14+), tested on one phone with a fake app; build it yourself.

What it can't do (yet)

Not built yet

  • Android works only through the companion APK you build yourself, tested on one phone with a fake app; no WebView logins, no saving new logins.
  • Passkeys: web sign-in on Chromium only. No counter write-back, no registration.
  • No WebKit/Safari. Firefox/Camoufox is opt-in.
  • No backend has been verified end to end on a live vault.
  • Shadow DOM, closed iframes and canvas inputs aren't detected, so it stops.
  • Not published to npm yet, and no independent security review.

Threat model, in plain words

blindfill defends against the model and its logs. It does not defend against:

  • A malicious or compromised page. The password is typed into the page's DOM, so scripts on a page you bound the item to can read it.
  • A compromised browser or machine. Anyone who can read process memory, the browser profile or your vault session wins.
  • Another tool on the same browser. A second tool attached to the browser can read a filled field.
  • Scrubbing is best effort. A page that transforms the secret can defeat it.

FAQ

Does the model ever see my password?

Not through blindfill: no command, tool or function returns a Secret-class value. The password does exist in the page's DOM once typed, and another tool attached to the same browser could read it, so don't give the agent an unrestricted browser tool for the same session if that matters to you.

Can it read my one-time codes?

The current 6-digit code is readable and fillable, like text. The TOTP seed is never returned. Its safety rests on origin binding and its short lifetime.

Which password managers work?

Bitwarden/Vaultwarden through bw is the verified-against-mocks backend. 1Password, rbw, pass, gopass, KeePassXC and Secret Service are blind-written and unverified. blindfill backend selftest <id> runs a fake-item round trip, and reports are welcome.

Which browsers work?

Chromium is supported and tested. Firefox/Camoufox is opt-in: tested against Camoufox 158.0.1-beta.41 and 159.0-beta.43 through a loopback Playwright server. Ego Lite works only as a separately launched, empty-profile instance. WebKit isn't supported.

What about phones and passkeys?

Android works through a companion APK (Android 14+): autofill for passwords and a credential provider for passkeys, with the signature made on the host. Tested on one phone (Android 17) with a fake app, not with real apps. Web passkeys work on Chromium only. Both were tested against fake relying parties: no counter write-back and no registration.

Is it safe to use on my real accounts?

It's alpha software with no independent review. Try it on throwaway or low-stakes accounts first, and read the threat model above.

What does it cost, and what's the license?

It's free and open source under the MIT license.

Give your agent a login it can't leak

The package isn't on npm yet (the latest tag there is an empty placeholder), so don't run npx blindfill. Build from source.

Requires Node 20 or newer and, for the one mock-verified backend, the Bitwarden CLI (bw). Steps follow the README's "Try it". 

git clone https://github.com/mics8128/blindfill && cd blindfill
npm ci && npm run build && npx playwright-core install chromium
export BW_SESSION="$(bw unlock --raw)"   # env only
mkdir -p ~/.config/blindfill && echo '{"backend":"bw"}' > ~/.config/blindfill/config.json
node dist/cli.js session start --headless
node dist/cli.js fill --item <id> --url https://example.com/login --submit
