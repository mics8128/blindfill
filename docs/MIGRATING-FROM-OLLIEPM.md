# Migrating from olliepm

blindfill is the public, TypeScript successor of `olliepm` (a private Python password-fill tool). This
page tells an olliepm user what maps to what, how to move data into your Vaultwarden (or any
Bitwarden-compatible vault), and, without overclaiming, which olliepm safety semantics are ported, partial or
missing. Status: alpha. Nothing here has been run against production secrets.

Key difference: olliepm kept items and secrets in a local store (`vault.json` plus the OS Secret Service).
blindfill keeps everything in the vault item itself (ARCHITECTURE.md section 3.4); there is no sidecar store.

Name clash: blindfill's `handoff pause|resume|status` (MCP `human_handoff`) hands the browser to a person
(CAPTCHA, consent, MFA). It is unrelated to olliepm's `handoff`.

Removed concepts: page IDs (blindfill acts on the current page of the attached context; `profile login
--page <index>` picks one), the per-process Unix-socket daemon, and item names as primary keys.

## 2. Data migration

Each olliepm item becomes one vault item. Do this by hand or with `blindfill item create`; there is no
scripted secret export (by design, nothing in blindfill returns a secret).

| olliepm                               | Vault item (Bitwarden/Vaultwarden)                                                                                                                                                                                                                                                      |
| ------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `origins[]` (exact https origins)     | `login.uris[]`, one per origin, match type **Host** (or stricter: Exact, Starts with). Avoid Base domain.                                                                                                                                                                               |
| field `username`                      | `login.username`                                                                                                                                                                                                                                                                        |
| field `password` (kind password)      | `login.password`                                                                                                                                                                                                                                                                        |
| field kind `totp`                     | `login.totp` (store the seed or otpauth URI)                                                                                                                                                                                                                                            |
| other `text` fields                   | custom field, type **Text** (readable, fillable by name)                                                                                                                                                                                                                                |
| other secret fields                   | custom field, type **Hidden** (fill-only)                                                                                                                                                                                                                                               |
| `rules[]`                             | custom field `blindfill.rules` = `{"version":2,"rules":[...]}`. The rule schema is unchanged; olliepm rule ids already satisfy blindfill's id pattern. Fallback: private file `<config dir>/rules/<item id>.json` = `{"version":1,"rules":[...]}` (mode 0600).                          |
| rule with `mode: registration`        | the same rule, plus custom field `blindfill.registration` = `allow` on the item                                                                                                                                                                                                         |
| `password_policy`                     | custom field `blindfill.password_policy` (same JSON schema, version 1)                                                                                                                                                                                                                  |
| submit behaviour                      | `blindfill.submit` = `once` (default) or `none`                                                                                                                                                                                                                                         |
| mobile target `package`               | extra URI `androidapp://<package>` (used by `blindfill android fill` and `blindfill android passkey`)                                                                                                                                                                                   |
| mobile target `signers` (64 hex)      | custom field `blindfill.signers`, comma-separated SHA-256                                                                                                                                                                                                                               |
| profile file `profiles/<name>.json`   | `blindfill profile init <name> ...`. Re-create or edit: `item` is now the **backend item id** (optional `item_name` guards against a swapped item); `default_target` and `phone` are dropped; the `revision` hash is recomputed, so re-run `profile validate` and use the new revision. |
| handoff grants `handoffs/<name>.json` | no equivalent (see section 4)                                                                                                                                                                                                                                                           |

Notes:

- olliepm required exact https origins. Bitwarden URIs can be looser; set match types deliberately.
- Secrets live in the OS Secret Service, not in `vault.json`. Moving them is a human step done in a
  terminal you control (olliepm's own local reveal, then the vault UI or `blindfill item create`). Never pass them
  through an agent, a log, a pipe or the clipboard.
- A malformed `blindfill.rules` or `blindfill.password_policy` value is currently ignored rather than
  refused (see section 3, row 6). Check with `page discover` after editing.
- Vault custom-field length limits may constrain very large rule sets [unverified]; use the local rules
  file in that case.

(deliberately different). "Tested" means a test exists in `tests/`; it is not an independent review.

## 4. Not ported yet

- **Android**: companion APK instead of scrcpy (ARCHITECTURE 3.2). No mobile registration or WebView logins yet; tested on
  one phone with a fake app.
- **Passkeys**: olliepm had none. blindfill signs web passkey logins in Chromium (`passkey` / `passkey_sign`, ARCHITECTURE 3.8);
  the sign counter is not written back and passkey creation is not supported.
- **Grants**: replaced by a per-call, one-time arm token for one item (Android); no standing grants.
- **Credential pipe export and local reveal**: intentionally absent.
- **Share daemon**: replaced by in-process `withPage`; there is no cross-process page lending.
- **Backends**: only `bw` has been exercised (mock plus hand-checked JSON); no end-to-end run on a live vault
  has been recorded in the repo. Other backends are unverified.

## 5. Cut-over checklist

1. Read SECURITY.md. Close the partial rows in section 3 that matter to you.
2. For each olliepm item: create the vault item (section 2); put it in a collection the agent may read; set match type Host.
3. Move rules and policies into `blindfill.rules` / `blindfill.password_policy`; set `blindfill.registration=allow` only where needed.
4. `blindfill item show --item <id>` (readable view) and `page discover` on the real page; no secret is read.
5. Re-create profiles with `profile init`, then `profile validate` and note the new revision.
6. Dry-run `fill` without `--submit` on a throwaway account; confirm the session locks and `session stop` unlocks.
7. Run the leak test locally; check that the audit file (`audit.jsonl`) contains no values.
8. Switch agent MCP config from `olliepm serve` to `blindfill mcp`. Remember `submit` now defaults to false.
9. Keep olliepm installed for credential-pipe uses and mobile registration until replacements exist; then retire its local store.
